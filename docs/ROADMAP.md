# 行会 AI · 发展路线

更新于 2026-10-09。本页描述演进顺序与进入下一阶段的条件，不承诺发布时间。除“当前已经具备”外，以下均为规划，尚未实现。

## 当前已经具备

本地网页工作区提供通用 AI 实践与游戏制作人两条路线，包含 20 个实践节点、20 份可编辑提示词配方和 13 个工具条目。三份本地成员档案各自记录学习进度、笔记与收藏，共用任务板和目标里程碑。已保存数据写入本机数据库，可以整体导出、校验后恢复；多个窗口写入发生冲突时会刷新并要求重试。

当前版本无需 AI API 密钥，不执行提示词。窄屏布局用于改善阅读与操作体验，不代表已发布手机 App。成员切换不是登录，工作区仅监听本机地址；其他电脑、好友和手机没有接入共享数据的能力。实际操作见[使用指南](USER_GUIDE.md)。

## 1. 先验证两条完整实践路线

先让三位内部使用者完成一次真实流程：选任务、准备材料、使用自己的 AI 工具、检查成果、保存经验。根据实际卡点改进课程、配方和任务板，保留有帮助的轻量 RPG 表达。

这一阶段的评价依据是用户能否完成交付物、能否说明哪里仍未验证、能否再次复用流程。课程完成数只表示个人进度；不引入战力、虚构熟练度或职业认证。新增功能优先解决已观察到的问题，不以公会数量或模板数量代替使用价值。

## 2. 让内容更新与数据升级可维护

规划引入内容版本、适用工具版本、核查日期、变更记录和失效反馈，让使用者能判断教程是否适用于自己的环境。来源正文、用户反馈和实际复测共同支持更新，不把一次模型成功输出当成永久保证。

当前课程与配方随代码发布，没有后台内容编辑或内容包导入；当前工作区数据结构是 **schema 1**。后续增加内容后台或导入机制时，需要分别管理应用数据版本与课程内容版本：

- 为公会、课程、配方和检查项保留稳定标识，防止排序或改名让已有进度错位；当前检查项按位置记录，结构变化前需设计明确迁移。
- 新增或删除内容时保留旧笔记及其来源说明，提供历史条目的去向；已保存提示词文本不被新模板直接改写。
- 新的数据结构必须提供版本识别、迁移校验与失败回退，在导入前展示影响；未知版本应明确拒绝，不静默丢字段。
- 当前备份导入是整体替换，不具备跨版本自动迁移、数据合并或内容包安装能力。后续升级须先验证现有 schema 1 备份仍有可用的恢复路径。

具体编写与复查要求见[内容编写规范](CONTENT_GUIDE.md)，不在此重复维护一套标准。

## 3. 建立真正的共享工作区

先建设共享服务、真实账户认证、成员权限与数据隔离，再开放异地协作。每次读写由服务端确认身份和权限，不能把当前的本地成员切换当成认证，也不能直接把本地服务暴露到公网。

规划支持跨设备访问同一工作区、邀请好友、组建学习小队、分配任务与共享目标；需要同时确定哪些笔记属于个人、哪些成果可向队友公开，以及退出小队后的访问规则。多人更新、冲突处理、数据导出与恢复必须在真实协作场景下验证。

进入这一阶段的依据是三人本地使用已证明核心流程有效，并且共享服务能够可靠区分用户与权限。好友、邀请、联网小队和实时同步目前均未实现。

## 4. 在稳定服务之上做手机体验

规划推出手机 App，围绕短时学习、收藏配方、记录成果和处理小队任务设计手机流程。技术形式先通过使用测试确定，不预设必须重做一套内容或使用某种框架。

手机与电脑应使用同一账户和明确的数据同步规则。离线草稿、消息提醒、系统分享入口等属于待验证方向；是否加入，取决于用户需求、平台能力与数据恢复方案。当前网页适配窄屏，但没有安装包、上架版本、推送通知或离线同步承诺。

## 5. 扩展职业与用户发布的小任务

新职业先交付一条完整而可验证的主线，再逐步增加案例。可探索研究与学术、数据分析、写作与出版、翻译与本地化、视觉设计、视频、音频、网页、应用开发、教育、办公自动化、产品协作、电商运营、空间与创客等方向。

**通用 AI 实践的边界是跨领域可迁移的方法，专业公会的边界是领域特定的交付物与验收标准。** 通用路线可以深入资料组织、信息核查、流程评测和自动化；质量判断需要学科知识、专用工具链或生产规范时，进入专项路线。相同工具不必另开公会，难度高也不自动归入专业。专业课引用通用前置课，避免重复整套基础内容。

用户发布小任务是后续独立能力：应先明确任务范围、材料权限、负责人、交付标准、验收与争议处理，再逐步试用。当前共享任务板只供本地三份成员档案协作，没有公开发布、陌生人接单、报酬结算或任务市场。收费和交易机制尚未确定，不作为首期功能前提。

每阶段都以实际使用反馈调整优先级；先把当前流程做稳，再增加需要新基础设施或新专业维护能力的功能。
